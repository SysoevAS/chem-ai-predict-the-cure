# Командная работа

## Распределение ролей

Работу делили на несколько зон ответственности:

- тимлид / интегратор - структура репозитория, контроль задач, финальная сборка pipeline, README и проверка submission;
- участник по EDA - анализ данных, пропуски, распределения target, константные признаки, выводы для моделирования;
- участник по baseline - первые модели, cross-validation, первые submission;
- участник по advanced-моделям - ансамбли, SI-эксперименты, target-wise stack, финальные overlay.

## Как шла работа

Сначала мы провели стартовое обсуждение задачи и договорились, что главная цель первого этапа - не сразу лучший score, а рабочий воспроизводимый pipeline.

После первого EDA отдельно обсудили несколько проблем:

- train маленький, а признаков много;
- `SI` имеет тяжёлый хвост;
- `SI` связан с `IC50` и `CC50`;
- часть признаков константная или почти константная.

После baseline-моделей стало понятно, что одиночные модели дают нестабильный результат. Поэтому дальше мы перешли к ансамблям и отдельным экспериментам по каждому target.

Самая большая часть обсуждений была вокруг `SI`. Мы проверяли разные варианты: предсказывать SI моделью, считать через формулу, смешивать модель и формулу, сглаживать хвост. В итоге остановились на смешивании модельного SI и формульного SI.

Ближе к финалу мы перестали добавлять крупные новые идеи и начали аккуратно сравнивать близкие версии submission. Основной принцип был: лучше небольшое стабильное улучшение, чем агрессивное изменение, которое может сломать распределение.

## Принятые решения

1. Для `SI` использовать не только модель, но и формулу `CC50 / IC50`.
2. Не пересчитывать `SI` на финальном этапе после каждого изменения `IC50` и `CC50`, если это ухудшает score.
3. Использовать target-wise stack только как небольшой дополнительный сигнал.
4. Финальный overlay делать только для `IC50` и `CC50`.
5. Финальный submission выбирать не только по идее модели, но и по фактическому Kaggle score.

## Итог

Командная работа шла итерационно:

```text
baseline -> анализ ошибок -> SI-эксперименты -> stack -> adversarial overlay -> финальный выбор
```
